# Sailships Combat

**Sailships Combat** — отдельный тактический режим для морских и воздушных корабельных боёв, а также сражений с летающими существами в Foundry VTT.

Текущая версия: **0.14.2**.

Совместимость:

- Foundry VTT 13.351;
- Forbidden Lands 13.0.5;
- сторонние модули не требуются.

## Установка

Полностью замените папку:

```text
Data/modules/sailships-combat
```

После перезапуска Foundry версия проверяется в консоли:

```js
game.modules.get("sailships-combat")?.version
```

Ожидаемый результат: `0.14.2`.

## Запуск

Кнопка модуля находится в инструментах **Journal Notes** левого меню сцены.

Макросы:

```js
game.sailshipsCombat.open();
game.sailshipsCombat.openBattleSetup();
game.sailshipsCombat.openShipyard();
game.sailshipsCombat.openSoundSettings();
game.sailshipsCombat.openBoardSettings();
```

## Основные окна

### Бой

Главное окно содержит поле, фазы раунда, список боевых единиц, управление движением, стрельбой, повреждениями, экипажем, существами и назначениями игроков.

Раунд состоит из четырёх этапов: приказы → манёвр → стрельба → экипаж. «Завершить раунд» обрабатывает длительные эффекты и открывает сводку. Стрельба начинается с явного выбора цели; батареи показывают прогноз или причину ограничения. После атаки доступна карточка фактических последствий «было → стало».

### Подготовка боя

Окно подготовки управляет:

- размером и режимом поля;
- ветром, морем и видимостью;
- условиями победы;
- командами, их цветами и зонами расстановки;
- готовыми и пользовательскими сценариями;
- генерацией террейна.

### Верфь

Верфь содержит текущий состав боя, встроенные шаблоны, библиотеку кораблей, бестиарий и редакторы боевых единиц. Состав группируется по командам. Глобальный селектор «Новые участники» определяет, в какую команду попадёт добавляемый корабль или существо, а команда выбранной единицы меняется отдельно на вкладке текущего боя.

Редакторы разделены на тематические разделы. Несохранённые правки переживают переключение разделов и участников, пока окно открыто. Кнопки применения и отмены находятся внизу формы. Встроенные каталоги и свои шаблоны поддерживают поиск.

### Настройки поля и звука

Настройки поля показывают предпросмотр изображения, его непрозрачность и размер плитки. Звук настраивается для текущего клиента: громкость, прослушивание и свой файл для каждого эффекта.

[Описание интерфейса и браузерных проверок](docs/module-workspaces.md).

## Бои с несколькими командами

Бой поддерживает три и более независимых команд. Любые единицы с разными `side` считаются враждебными друг другу. Названия, цвета, правила огня по ядру и зоны расстановки задаются отдельно для каждой команды.

Автоматическая победа в режиме «бой до решения» наступает только после того, как боеспособной остаётся одна участвующая команда. В режиме прорыва несколько независимых защитников не получают произвольно назначенного общего победителя.

## Данные и синхронизация

Начиная с версии 0.14.0 полный бой больше не хранится в доступном всем клиентам world setting. Авторитетное состояние размещается в служебных JournalEntry-документах с правами Foundry и разделяется на три части:

- основное состояние боя;
- журнал;
- краткоживущие события движения, звука и столкновений.

Сохранения, библиотека кораблей, бестиарий и пользовательские сценарии также перенесены в GM-only документы. Для каждого игрока создаётся отдельная проекция боя, доступная только этому игроку и ГМам. Служебные документы скрываются модулем из каталога Journal Notes.

При первом запуске 0.14.0 ведущий активный ГМ автоматически переносит данные из прежних world settings. Старые настройки после успешного переноса заменяются безопасными указателями без содержимого боя.

Внутренний массив участников по-прежнему называется `battle.ships` ради совместимости, но поддерживает два типа:

```js
unitType: "ship"
unitType: "creature"
```

Текущая схема данных: **v13**.

## Транспорт и граница доверия

Приватность состояния обеспечивается правами документов Foundry. Команды игроков и ответы ГМа подписываются HMAC-ключом, который хранится только в персональной проекции игрока. Это не позволяет одному обычному клиенту выдавать себя за другого игрока без доступа к его документу.

Core socket по-прежнему рассылает всем клиентам несекретные метаданные обновлений: revision, область рендера и причину изменения. Безопасность зависит от корректной работы document ownership Foundry и прав пользователей мира.

## Миграции и диагностика

Начиная с версии 0.14.1 схема боя обновляется строго последовательно: `v0 → v1 → … → v13`. Модуль отдельно мигрирует активный бой, сохранения, библиотеку кораблей, бестиарий и пользовательские сценарии. Повторный запуск миграций не меняет уже актуальные данные.

Данные из более новой, неизвестной версии схемы не понижаются молча. Модуль останавливает загрузку такого объекта с явной ошибкой, чтобы не повредить сохранение.

Диагностика хранилища запускается ГМом из консоли:

```js
game.sailshipsCombat.runDiagnostics();
```

Отчёт проверяет ведущего записывающего ГМа, наличие и права служебных документов, схему и размер боя, уникальность ID, актуальность персональных проекций, версии коллекций и очистку старых world settings. Метод также возвращает объект отчёта:

```js
const report = game.sailshipsCombat.runDiagnostics({ log: false });
console.log(report.ok, report.counts, report.checks);
```

## Проверки разработки

В архив включён автономный набор проверок без внешних зависимостей. Требуется Node.js 20 или новее.

```bash
npm test
npm run check:module
npm run check
```

`npm test` запускает проверки миграций, нормализаторов, движения, столкновений, стрельбы, повреждений, существ, условий победы, боёв с несколькими командами, документного хранилища, персональных проекций, HMAC-подписей, конфликтов revision и диагностики. `npm run check` дополнительно проверяет JSON, синтаксис JavaScript, относительные импорты, пути из `module.json` и соответствие ключей локализаций.

## Обновление с 0.13.x

Перед обновлением рекомендуется сделать резервную копию мира. Первый запуск должен выполняться при подключённом ГМе. Не удаляйте JournalEntry-документы с префиксом `Sailships Combat ·`: это внутреннее хранилище модуля, даже если записи скрыты из каталога.

## Обновление интерфейса в рабочей ветке

Текущие исправления ревью и изменения окна описаны в [журнале работы](docs/review-and-interface.md). Вверху панели управления показано, что делать сейчас. Кнопки завершения действия и перехода фазы подписаны; боеприпас и режим выбираются непосредственно в карточке залпа.

Предпросмотры доступны в **Actions → Module checks → interface-preview**: шесть фаз на трёх размерах окна, PNG и HTML. Они используют настоящие шаблоны модуля и демонстрационные данные в упрощённой оболочке Foundry.


В фазе движения сначала выберите подсвеченную клетку: появятся маршрут, конечный курс и карточка прогноза. Подтвердите манёвр на поле или отмените его кнопкой/клавишей Escape. До подтверждения можно выбрать другую клетку без расхода ОД. Подготовительные действия с парусами и ядром выполняются сразу; после них маршрут выбирается заново.


В фазе экипажа выберите конкретную аварию: секцию с пожаром или водой, пробоину, завал, повреждённую систему или ядро. Карточки показывают стоимость, прогноз и риск; результат сохраняется в отчёте боя. Абордаж и защита палубы вынесены отдельно. Недоступный в бою ремонт объясняется в раскрываемом блоке.

Контрольный прогон четырёх кораблей: `node tools/audit-combat-tempo.mjs`. Он проходит настоящие контроллеры четырёх фаз на двух сценариях и трёх фиксированных seed; JSON с исходными условиями, действиями и итогами доступен в **Actions → Module checks → combat-tempo**. Методика, результаты и ограничения: [аудит темпа](docs/combat-tempo-audit-2026-10-08.md).

Браузерная проверка экипажа: `node tools/preview-crew.mjs` после установки тех же инструментов, что использует workflow. Она проверяет реальные шаблоны и команды на четырёх размерах окна; снимки входят в артефакт `interface-preview`.
